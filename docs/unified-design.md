# Codex Synced 统一设计规范

## 设计目标

macOS 和 Windows 使用同一套“诊断 → 预览 → 备份 → 写入 → 复核”的心智模型。平台差异只体现在原生控件与窗口布局，不改变风险等级、确认边界、字段保护或验收文案。

## 统一信息架构

两端页面顺序固定为：

1. **首页**：环境、Provider、状态库、扫描状态、最近备份和下一步动作。
2. **待修复项**：普通摘要修复预览、备份模式、分页风险和可安全重算项目。
3. **对话修复**：分页 lineage 只读诊断、单条入口修复、条件撤销。
4. **备份**：备份清单、模式、大小、修复摘要和恢复确认。
5. **设置**：语言、Codex Home、SQLite Home、备份策略、Provider 可见性和修复后启动。

## 统一风险分层

| 等级 | 页面文案 | 自动动作 |
| --- | --- | --- |
| 普通修复 | 备份并修复 | 只改已证明安全的 SQLite 摘要、索引、mtime 和旧格式 metadata |
| 分页可安全重算 | 独立确认 | 先做 SQLite/rollout 副本试写，再同步首行、`history_base`、turn 和 projection |
| 人工复核 | 需要人工确认 | 只读显示原因，不猜测入口、不写入 |
| 客户端验收 | 重启后核对 | 不把哈希、`quick_check` 或入口更新冒充正文读取完成 |

## 统一安全边界

- 写入前检测 Codex Desktop、CLI 和 app-server；不杀进程。
- 写入前创建 WAL 一致备份；分页写入额外创建历史库和 rollout 副本。
- 使用旧值 compare-and-swap、文件哈希、SQLite 完整性和过期预览检查。
- 不修改正文、逻辑 ID、物理 ID、项目归属、Provider URL、Token、Key 或 Codex.app。
- 失败恢复只使用本次备份；撤销只反向修改本次入口字段，不覆盖新活动。

## 统一视觉语言

- 蓝色表示可执行或信息，绿色表示已收敛，橙色表示风险/人工复核。
- 页面标题、状态卡、风险卡、主按钮、次按钮、进度条和空状态使用同一语义名称。
- 路径、ID、偏移和哈希使用等宽字体；正文风险提示始终可复制。
- 中英文切换不改变布局和操作顺序；Windows 保存语言设置，macOS 通过 UserDefaults 保存。

## 验收要求

每次发布必须通过 macOS Swift tests、Windows self-test、双平台 Release 构建和安装包生成；真实数据仍需用户重新打开并重启 Codex，逐条核对顺序、遗漏、重复和项目归属。
