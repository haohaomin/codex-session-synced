# Codex Synced v1.5.0

This release tightens history visibility repair after switching Codex Providers and makes the backup/verification boundary explicit.

## Added and improved

- Provider diagnosis, paginated-risk warnings, WAL backups, and verification guidance now share one preview workflow.
- Legacy-format rollouts remain eligible for alignment to the active root Provider; paginated rollout headers remain byte-for-byte protected until `history_base` offsets can be recalculated safely.
- Lightweight backups retain the live database, WAL, and SHM files and create SQLite Backup API snapshots for present `state_*`, `thread_history_*`, and `logs_*` databases.
- Explicit temporary, repair, and backup artifacts are ignored; an unknown rollout only blocks chats in its own directory.
- Pending Repairs and Chat Repair use consistent risk cards that distinguish metadata repair from client-side body acceptance.
- Regression coverage now includes scoped unknown files, ignored leftovers, and backup boundaries.

## Manual-review boundary

Paginated Provider mismatches and all byte-offset inconsistencies still require manual review. The app never concatenates message bodies, rebuilds JSONL, or guesses a branch from file modification time. After an entrypoint repair, reopen the chat and restart Codex to verify message order, omissions, duplicates, and project ownership.
