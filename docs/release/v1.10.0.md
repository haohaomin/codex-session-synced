# Codex Synced 1.10.0

## 对话修复页不再“点击没反应”

- 新增状态库文件选择。根目录和 sqlite 子目录同时存在状态库时，可明确选择需要诊断的文件；自动模式仍拒绝歧义，不按修改时间猜测，不要求删除旧库。
- 选择仅用于对话诊断、入口修复及撤销，不改变普通 Provider 修复配置。目录变化后清除选择；失效或链接目标会被拒绝。
- 扫描显示进行中、失败原因及完成数量；重复操作禁用。打开修复记录目录失败时显示原因，不再静默无反应。
- 修复记录与备份列表独立加载，不再被状态库选择或扫描错误挡住。

## 可恢复的备份删除

- 备份页统一列出普通备份和对话修复备份，展示时间、路径，逐条确认删除并刷新结果。
- macOS 移到系统废纸篓；Windows 移到当前 Codex Home 的 `codex-synced-deleted-backups`，不依赖回收站是否启用。
- 删除前重新核对目录和描述文件，拒绝根目录、越界、链接、记录不匹配或确认后发生变化的备份。不会永久删除作为失败回退。
- 移回原位置和原文件夹名后刷新即可重新使用。备份移走期间不能恢复或撤销对应修复；不会改写活动对话、数据库或 Provider 配置。

## 验证与限制

- 本地 Swift 57 项测试、Windows 备份测试 34 个断言及更新检查 58 个断言通过；两端 Release 构建通过。
- macOS 独立测试应用实际验证了错误反馈、选择后扫描、打开目录、取消删除、移到废纸篓与放回后刷新；两个测试数据库及 JSONL 哈希保持一致。没有删除真实用户备份。
- 发布由 macOS Swift 测试与 Windows 自测、备份测试和更新测试门禁控制；Windows 原生 UI 仍需实机验收。
- 更新检查仍使用 GitHub API，匿名请求可能限流；本版本未加入静态更新清单或自动安装，也没有独立更新签名。SHA256SUMS 用于完整性核对，不等同于签名。
