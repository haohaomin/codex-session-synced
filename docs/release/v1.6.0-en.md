# v1.6.0

## Safe paginated Provider repair

This release moves paginated rollout Provider repair out of the ordinary sidebar button so SQLite metadata cannot be changed while inherited byte boundaries remain stale.

- Builds a global physical-branch index and validates unique lineage, parents, tips, ordinals, and byte boundaries.
- Computes the first-line byte delta and updates descendant `history_base`, `thread_turns`, and projection offsets.
- Trials the complete operation on SQLite Backup API snapshots and uniquely isolated rollout copies; message bodies are never rebuilt or concatenated.
- Uses compare-and-swap checks, body hashes, and backup recovery for live writes.
- Shows diagnostics in the UI and exposes only fully validated repairs through a separate confirmation flow.

The full Swift test suite and Release build pass. The macOS DMG is published; Windows retains the previous release pipeline. After a repair, reopen and restart Codex and manually verify message order, omissions, duplicates, and project ownership.

See the [implementation plan](../paginated-provider-repair-plan.md) for the safety boundaries and acceptance sequence.
