# 1.7.0 发布与验收方案

## 目标

在不触碰用户真实 Codex 数据的前提下，发布 Windows/macOS 统一修复能力。发布包必须同时通过 Windows 自测、macOS 测试与 DMG 构建，GitHub Release 只在全部平台成功后公开。

## 实施顺序

1. 先修复发布脚本的跨环境问题：当未提供 `CODEX_SDK_PATH` 时不展开空 Swift 参数数组。
2. 修正 Windows 隔离 self-test 的 rollout 文件名和 UUID，使样例符合真实文件命名规则。
3. 本地执行 Windows Release 编译；macOS 执行 Swift 测试和 DMG 构建，确认产物可生成。
4. 提交并推送修复，手动触发 `v1.7.0` 发布工作流。
5. 逐项检查 Windows self-test、Windows publish/MSI、macOS Swift tests、macOS DMG 和 publish job；失败只修复对应构建问题，不修改真实历史库。
6. 全部成功后核对 Release 资产、SHA256SUMS、README 下载链接和中文/英文发布说明。

## 验收标准

- Windows self-test 通过，覆盖普通 Provider、入口修复、分页 lineage、50 字节中间偏移、CAS、备份恢复和正文哈希保护。
- Windows MSI/ZIP 与 macOS DMG 均生成并上传，版本号均为 `1.7.0`。
- macOS Swift 测试全绿，DMG 内应用可启动且包含修复页面。
- 发布说明明确：分页修复必须独立确认；入口/偏移写入成功不等于桌面端正文逐条验收完成。
- 不杀 Codex 进程、不清空数据库、不拼接或重建正文；真实数据修复仍要求先备份并在副本验证。

## 发布后人工验收

安装新版本后，用真实副本打开三个异常对话，逐条检查顺序、遗漏、重复和项目归属；退出并重启 Codex 后再次检查。发现 50 字节偏移或旧人工合并轮次问题时，先保留备份和诊断输出，再决定是否执行最小修复。
