# Codex Synced 1.8.0

1.8.0 completes the cross-platform repair design and closes the remaining parity gaps after 1.7.0.

- Windows now persists the selected UI language, matching macOS settings behavior.
- Windows refuses writes while Codex Desktop, `codex-cli`, or `codex-app-server` is running.
- Windows Chat Repair now requires one unambiguous state database when the SQLite directory is auto-discovered, scopes unknown rollout-file blocking to the affected directory, and verifies the entrypoint change on the SQLite trial copy before committing.
- macOS Chat Repair verifies the requested entrypoint on its trial copy as well.
- The unified design specification documents the shared information architecture, risk levels, safety boundaries, visual language, and release gates.
- Validation records and README pages now describe Windows Chat Repair as shipped rather than experimental/macOS-only.

Safety boundary remains unchanged: no message-body concatenation or reconstruction, no changes to tokens, keys, provider URLs, project ownership, logical/physical IDs, or Codex.app. File hashes and SQLite checks prove local write safety; reopen and restart Codex to complete manual message-level acceptance.

Validation: 41 macOS Swift tests, Windows self-test, Windows Release/MSI/ZIP, macOS DMG, and the unified publish workflow must all pass before release publication.
