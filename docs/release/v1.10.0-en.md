# Codex Synced 1.10.0

## Responsive Chat Repair workflow

- Select an explicit state-database file when multiple candidates exist. Automatic mode still rejects ambiguity; it never guesses by modification time or requires deleting databases.
- The selection affects Chat Repair only. Directory changes clear it; stale and linked selections are rejected.
- Scans show progress, actionable errors and completion counts. Duplicate operations are disabled and folder-opening failures are visible.
- Repair records and backup inventory are independent of scan success.

## Recoverable backup deletion

- Ordinary and chat-repair backups are listed together with dates, paths and per-item deletion confirmation.
- macOS uses Trash. Windows moves backups to `codex-synced-deleted-backups` under Codex Home, regardless of Recycle Bin availability.
- Revalidation rejects out-of-root targets, links, mismatched manifests and changed selections. There is no permanent-deletion fallback.
- Move the folder back to its original path and name, then refresh to recover. Restore/rollback is unavailable while its backup is removed. Live chats, databases and Provider configuration are not modified.

## Verification and limitations

Local validation passed: 57 Swift tests, 34 Windows backup assertions, 58 updater assertions and both Release builds. A separate macOS QA application exercised selection, scanning, folder opening, cancellation, Trash deletion and recovery; fixture database/JSONL hashes remained unchanged. Real user backups were not deleted. CI gates publication on both platforms' tests; native Windows UI still requires real-device verification.

Update checks still use GitHub's API and may hit anonymous rate limits. Static manifests, automatic installation and independent updater signatures are not included. SHA256SUMS verifies integrity, not publisher signatures.
