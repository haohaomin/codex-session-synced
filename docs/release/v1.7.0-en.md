# Codex Synced 1.7.0

This release brings the repair entrypoints on Windows and macOS to the same safety model:

- Windows adds **Chat Repair** with read-only paginated lineage diagnosis, minimal `rollout_path` repair, and guarded rollback.
- Windows paginated Provider repair is separate from ordinary Provider alignment. It requires a unique physical lineage and validated `history_base`, `thread_turns`, and projection offsets before confirmation.
- Paginated writes use SQLite Backup API snapshots for state/history databases, isolated rollout trials, compare-and-swap metadata, body hashes, and failure recovery.
- Both platforms present the same risk layers: ordinary repair, validated paginated repair, manual-review diagnostics, and post-restart manual verification.
- README and the Windows paginated repair plan document the platform boundary and acceptance requirements.

Safety boundary: the tool never concatenates or rebuilds message bodies and never changes tokens, API keys, Provider URLs, project ownership, or Codex.app. Passing file-hash, SQLite-integrity, and offset checks proves local metadata/entrypoint safety only; reopen and restart Codex to verify message order, omissions, duplicates, and project ownership.

Verification: Windows Release build and `--self-test` run in the Windows CI job; the same release workflow runs the macOS Swift tests and DMG build.
